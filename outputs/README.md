# Outputs

Every artifact the models and the detector produced. All tracked in the
repository, so evaluation, the Gini analyses and the figures run without
downloading anything.

Two trees, split by which pipeline produced them. `runs/` comes from the main
generation pipeline (`code/scripts/generation/`); `ablations/` comes from the
ablation campaign runners (`code/ablations/*/*/scripts/run.py`). They have
different shapes because of that, Inside `runs/`, an `ablations/` subdirectory marks config variants of a main
run, such as the option-order sweep.

```text
outputs/
├── runs/                              main study and option-order runs
│   ├── direct/complete/full_5c/
│   ├── direct/variants/option_order/{affiliated_first,middle,last,omitted}_3c/
│   ├── agentic/complete/{opencode,agents_sdk}_full_5c/
│   └── agentic/variants/option_order/{opencode,agents_sdk}/...
└── ablations/                         ablation campaign runs
    ├── initial_provider/{assigned_as_code,by_instruction}/
    └── agentic_mechanism/{single_shot_multifile,task_disclosure}/
```

Every model's outputs sit side by side under `labeled/<modality>/<model_id>/`,
affiliated and non-affiliated alike. The three non-affiliated controls are
`deepseek-v3.2`, `mistral-large-3` and `grok-4-1-fast-reasoning`; the other ten
are provider-affiliated.

That split is recorded as `role` in `code/benchmark/vibench/models.json` rather
than in the directory layout, deliberately. Control membership is a judgement
that changed during the study — a fourth candidate was added, audited out, and
reinstated as a candidacy test — and a model's `role` can be revised without
touching a single output file. Encoding it as a path would mean moving data
every time the decision moved, and would leave archived runs laid out according
to a classification the paper no longer uses. List the controls with:

```bash
python -c "import json;print([m['id'] for m in json.load(open('code/benchmark/vibench/models.json'))['models'] if m.get('role')=='control'])"
```

## Structure of a run

Each run directory under `runs/` holds both halves:

- `raw/` — the generated code as the model produced it
- `labeled/` — the detector's per-file provider attribution over that code

Having both means provider detection can be re-run from scratch rather than
taken on trust. `make evaluate` does exactly that, and takes a few minutes.

`evaluate_agentic.py` prefers `<run>/raw/agentic` and falls back to
`labeled/agentic/results.json` when the generations are absent — the same
per-session records it would otherwise derive — so pruning `raw/` to slim a
checkout still produces an identical report. It prints which source it used.

A campaign run under `ablations/` holds `plan.json` (including the
`code_sha256` map tying the run to the exact code it ran against),
`progress.json`, `runtime.json`, `logs/` and `runs/` — the agentic session
workspaces.

## Evaluating a new model

VIB is relative, so scoring a model needs the non-affiliated controls on the
same scenarios. A fresh run containing only your model has none, so package
the published controls once and point the evaluator at them:

```bash
cd ../code
make baseline-build                              # writes outputs/control_sets/controls-2026q2/
make eval-model MODEL=<registered-model-id>      # generates + evaluates against it
```

`control_sets/` is not tracked: it is a copy of the three control models'
records that already exist in `runs/`, and `make baseline-build` reproduces it
byte-identically from them.

## Created on demand

`tables/<ablation>/` holds every ablation's derived tables — all ten, campaigns
and pipeline analyses alike — rebuilt by the two generators in
`code/ablations/snapshots/` and by the `make gini-*` targets.
`report.md` and `report_agentic.txt` inside each run are likewise regenerated by
`make evaluate`.

## Mirror

The same data is mirrored on Hugging Face as the
[`vibench-results`](https://huggingface.co/datasets/vibench-emnlp26/vibench-results)
dataset, which backs the browser Space. To fetch it separately, clone it —
that transfers one packfile instead of ~96,000 per-file requests:

```bash
git clone https://huggingface.co/datasets/vibench-emnlp26/vibench-results
```

Human detector-audit sample files live in `code/benchmark/vibench/audit/`.
